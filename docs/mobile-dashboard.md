# 모바일 대시보드

- 사용자 ZIP의 `Mobile.dc.html` 화면을 767px 이하에서 사용한다. 너비는 화면에 맞추고 높이는 `100dvh`다. 큰 화면에서는 기존 대시보드가 유지된다.
- 원본 색상·타이포그래피·간격·모션·하단 탭·설정 시트·레시피 조리 화면을 재사용한다. 서비스명은 디미, 로고는 컬러 구슬, 봇은 `@dimi_in`이다.
- `dashboard-mobile.js`는 기존 앱 상태와 `allItems()`를 읽는다. 별도 사용자나 콘텐츠 저장소를 만들지 않는다. 같은 로그인·계정 연결·목록 제외·즐겨찾기·레시피 체크·조리 타이머를 사용한다.
- 실제 데이터에서 DM 수신 방식은 서버 설정을 변경한다. 기본은 짧은 DM과 개인 결과 링크다. 상세의 공유 버튼은 로그인한 본인만 볼 수 있는 결과 주소를 복사한다. 공개 공유를 만드는 기능으로 표시하지 않는다.
- 데모 계정 이름·핸들 대신 현재 로그인/연결 정보를 표시한다. 실제 데이터에서 원본 시안의 가상 일정과 AI 취향 제안은 숨긴다. 구현되지 않은 동작은 준비 중이라고 안내한다.
- `scripts/build-dashboard.py`가 모바일 템플릿·모델·CSS·자산을 생성한다. 모바일 CSS는 media 조건으로만 적용하며, 데스크톱 디자인 원본은 변경하지 않는다.

검증: `node --test dashboard-mobile.test.mjs dashboard-live.test.mjs dashboard-frontend.test.mjs`, `python -m unittest scripts/build_dashboard_test.py`, `npm run build`.

실제 브라우저에서는 Gemini로 정리한 두 테스트 레시피를 사용했다. 520px 화면의 탭·상세·재료 체크·조리 단계 이동, 390×843 레시피와 조리 화면, 320×640 설정의 기본 링크 수신 옵션을 확인했다. 390/320 화면의 문서 너비가 각 뷰포트 너비와 같아 가로 넘침이 없었고, 이미지 로드 실패도 없었다. 데스크톱 1280px은 기존 디자인을 유지했다. 조리 버튼의 hover 배경·글자 대비도 확인했다.

모바일 Google OAuth 재로그인과 실제 Instagram 앱 안의 링크 열기는 이번 모바일 화면 검증에서 새로 실행하지 않았다. 기존 로그인·계정 연결 API를 재사용한다.
