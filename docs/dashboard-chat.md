# 대시보드 디미 채팅

## 동작

- 입력하는 동안: 현재 보관함에서 제안만 표시. Gemini 호출 없음.
- 옵션 버튼: 기존 콘텐츠 필터/검색을 실행하고, 입력 중 표시를 최소 1.5초 유지. 일반 카테고리·최근·취향 버튼은 모델 호출 없음. ‘매콤한 레시피’처럼 의미 검색이 필요한 버튼은 기존 검색 API 사용.
- 직접 보낸 문장: `/api/dashboard-chat`에서 Gemini로 답변과 관련 카드 ID를 한 번에 생성. 인사·일상 대화·기능 안내·자연어 콘텐츠 검색·저장 결과 후속 설명 지원.
- 모델 설정과 말투: `dimi-persona.mjs`를 DM과 공유. `GEMINI_CHAT_MODEL`, 없으면 `gemini-3.5-flash-lite` / `minimal`. 기존 `GEMINI_API_KEY` 사용. 미디어 분석 모델은 변경하지 않음.
- 대화 중 입력 중 표시는 모델 응답이 더 오래 걸리면 계속 유지한다. 1.5초는 답변 완료를 보장하는 시간이 아니다.

## 데이터와 접근 범위

현재 로그인 JWT를 Supabase Auth로 확인하고, 그 JWT 그대로 RLS가 적용된 결과와 취향 목록을 조회한다. 요청 본문의 사용자 ID나 콘텐츠 본문은 신뢰하지 않는다. 서버에서 현재 성공한 결과를 대시보드 변환기로 카드별로 나눈다. 숨긴 결과는 제외한다.

최근 최대 200개 카드의 제목·분류·요약·색인과, 질문/선택 카드/이전 대화에 관련된 최대 6개 상세를 전달한다. 전시 등 한 게시물의 여러 카드는 각자의 ID와 정보로 구분한다. 모델이 반환한 ID는 다시 본인에게 허용된 현재 카드 목록과 대조한다. 검색 벡터·계정 식별자·토큰·미디어 파일은 모델에 보내지 않는다.

최근 12개 메시지는 현재 웹 화면 메모리에만 유지한다. 새 대화, 계정 변경, 페이지 새로고침으로 초기화된다. DM 대화 기록을 읽거나 합치지 않는다. API는 대화 기록을 저장하지 않는다. 일반 대화도 모델 제공자에게는 전달된다.

## 범위 밖

웹 채팅에서 새로운 릴스/URL 다운로드·분석, 외부 웹 검색, 일정·취향 변경, 예약·지원·발송을 수행하지 않는다. 기존 저장 결과 조회와 일반 조언만 지원한다. 새 콘텐츠는 Instagram DM으로 보내도록 안내한다. 상세에 없는 수량·날짜 등은 추측하지 않도록 지시하며 관련 카드로 연결한다.

## 실패와 운영

모델/저장소 장애는 다시 시도 안내로 표시하고 가능한 로컬 검색 카드만 제공한다. 새 대화/계정 변경 후 이전 요청이 늦게 끝나도 화면에 섞이지 않는다. 입력/대화 크기, 역할, ID, 응답 길이를 검사한다. 키는 서버 환경변수만 사용한다.

서버 인스턴스별 동시 요청/연속 요청 제한을 둔다. 여러 인스턴스에 걸친 영구 사용량 제한은 아니므로 일반 공개 규모 확대 시 공유 쿼터를 추가한다. 데이터베이스 스키마·정책 변경 없음.

검증: `node --test dashboard-chat-api.test.mjs dashboard-home-chat.test.mjs dm-assistant.test.mjs`와 `npm run build`. UI 실제 Gemini 확인은 배포 후 별도로 기록한다.

## 화면 이동

데스크톱 홈(`/dashboard`)은 시작 화면을 유지한다. 질문 또는 빠른 옵션을 보내면 `/chat`으로 이동하고 사이드바의 채팅 탭이 활성화된다. 홈이나 다른 탭을 봤다가 채팅을 누르면 현재 화면 세션의 대화가 복원된다. 새 대화는 대화만 비우며 보관함은 삭제하지 않는다. 모바일의 기존 홈/하단 탭 디자인은 이번 변경 대상이 아니다.
