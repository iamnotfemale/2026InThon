# 처리 결과 저장·전송과 목록 관리

- 새 결과는 `status: done`일 때만 `factchecks`에 저장한다. `failed`, `no_input`, `not_checkable`은 DM으로 사유만 안내한다. 대시보드도 `done`만 조회하므로 이전 실패 기록은 목록에 보이지 않는다. 자료를 읽고 근거 부족으로 `unverified` 판정한 정상 완료 결과는 유지한다.
- 기본 전송은 **핵심 안내 + `/items/fc<저장된 ID>` 고유 링크**다. 본인 로그인·계정 연결에 적용되는 기존 Supabase RLS를 그대로 사용한다. 공개 공유 권한은 만들지 않는다.
- 설정 → ‘DM 결과 받는 방식’에서 ‘DM에서 전체 받기’를 선택하면 기존 전체 응답을 나눠 보낸다. 선택은 앞으로 처리하는 결과부터 적용된다. 저장을 확인하지 못한 경우에는 없는 링크를 보내지 않고 DM 본문으로 전달한다.
- `result-preferences.mjs`는 Google 사용자별 전송 방식과 목록 제외 표식을 private Blob에 저장한다. `POST /api/instagram-link`의 `preferences` 동작이 기존 서버 Google 세션 검증을 거쳐 읽고 쓴다. 브라우저가 보낸 사용자 ID는 사용하지 않는다.
- 봇은 `account_links`에서 현재 DM 발신자와 연결된 Google 사용자를 조회해 그 사용자의 받는 방식을 적용한다. 연결 사용자가 없거나 설정이 없으면 기본 고유 링크 방식이다.
- 목록의 **삭제는 본인의 목록에서 제외하는 방식**이다. 서버 분석 원본을 영구 삭제하지 않으며, 알림의 ‘되돌리기’로 복원할 수 있다. 제외 표식은 계정별로 보관하므로 새로고침·다른 기기에서도 유지된다. 상세 페이지에서도 제외된 항목은 목록에 포함하지 않는다.
- 행 메뉴는 브라우저 Popover의 최상위 레이어에 표시해 다른 행의 애니메이션·스크롤 영역에 가려지지 않는다. 화면 아래에서는 메뉴를 위로 열고, 바깥 클릭·Esc로 닫는다. 방향키·Home·End로 메뉴 항목을 이동할 수 있다.

새 DB 테이블이나 역할 권한은 추가하지 않는다. 기존 실패 기록을 물리 삭제하지 않으며, 앞으로 실패 결과가 새로 업로드되는 것을 차단한다.
